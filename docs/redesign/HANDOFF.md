## Standing rules

From section 0.1 of the brief, with what the work has added since. They bind every commit, pull request, file and board.

1. **No AI references anywhere.** Not in commits, pull request titles or descriptions, code, comments, tests, docs, changelogs or boards. No co-author lines, no session links, no footer lines about how the text was made. Commits and pull requests read as plain text written by a person.
2. **Read the real file before you change it,** and match the repository's conventions (helpers, naming, response shapes, the test harness). The brief names paths as they were on Mon, Oct 5, 2026. If the code has moved, follow the code and note the difference in `REDESIGN_STATUS.md`; checkpoint C's moves are mapped from old path to new in `scripts/moves/*.json`. Items marked `verify:` are checked first.
3. **Collect only what is needed.**
   - Eligibility is confirmed with a checkbox ("In 8th grade or below?"). Never ask for a child's grade or birthdate.
   - LCA does not get involved in families' finances: no fee waivers, and no lunch-status or need-based questions.
   - Results, standings, winners and recaps show players' full names, children included. Only a page that lists minors and nothing else, such as a full scholastic roster, shortens them to first name and last initial.
4. **Keep the hard-coded "300+ members" figure, and keep every Facebook link.** The Facebook feed is pulled on the server.
5. **Partner events register on the organizer's site; LCA-run events register on louisianachess.org.** Partner events are the Gulf South clearinghouse listings. They never get a Register button or an entry count, and they say "Registers on the organizer's site ↗".
6. **WCAG 2.2 AA.**
   - Status is always shown in words beside its colour, never by colour alone.
   - Brand gold `#c8a94a` is never text on a light ground (2.28:1). Gold text is `#866a1e` (5.13:1 on white).
   - Gold text on navy `#1a2744` is fine (6.51:1).
7. **Plain language.**
   - "US Chess" and "US Chess ID", never the old initials, in anything a person reads.
   - Every date carries its weekday: "Sat, Oct 24".
   - Times are written "7:00 PM".
   - Half points are ½, never 0.5 or 3.5.
   - Chess shorthand gets a plain companion the first time: "G/90+30 · 90 min each + 30 sec per move".
   - No em dashes anywhere: copy, board notes, docs, commits and pull request text.
8. **Previews never touch production.** Since WS01 step 1, a preview is bound to `lca-db-preview` through `[env.preview]` in `wrangler.toml`. Nothing run for a preview may reach `lca-db`, the live site, a Pages production address, or a single deployment's own address (`<8 hex characters>.lca-website.pages.dev`), which can run on production data. The preview database is migrated from the branch before anyone reviews a checkpoint's preview: the lead's session runs the guarded script (the one preview write it may make) and K may run it too. ## Security

- Never print or write the Cloudflare token or account values: not in a command, a log, a record, a commit or a pull request. The Pages bot's comments on pull requests carry account values in their dashboard links, so never copy those links.
- The production database `lca-db` is read-only: one `SELECT` per command, and never a migration. Merging to `main` migrates production (`.github/workflows/migrate-db.yml`), and K applies any other remote migration. That job can fail on a transient Cloudflare error before it applies anything; watch it on every merge that carries a migration and re-run the failed job at once (see "Workflow gotchas"). Locally, migrations run with `npm run db:migrate:local`.
- The only write to the preview database is `npm run db:migrate:preview`.
- A write to production data from a cloud session (such as the membership apply) needs a helper session whose permission mode asks a human before each command, so that K approves every command in the web UI. A session in auto mode is refused by its automatic permission check, as the first apply attempt on Tuesday, November 3, 2026 was (nothing was written), and the lead never works around that refusal. Create the helper with permission mode "default", give it the plan inline, and tell it never to print a value from the environment. The lead's own checks afterwards are read-only SELECTs, one per command.

## Workflow gotchas

- Resuming a workflow replays only the longest unchanged prefix of its agent calls, in call order. A changed call, and every call after it, runs again.
- An agent that returns more than 64k output tokens fails. Critics and reviewers return compact corrections, never a rewritten document.
- An interrupt kills the agents in flight.
- **Never `git add -A` in a worktree whose `node_modules` is a symlink; stage by path.** Commit `e58891c` (the step 9 merge-review fix, made in the WS02 worktree) tracked the link, because `.gitignore`'s `node_modules/` matches a directory only, not a symlink. It reached `main` in PR 119's merge. Two harms followed. GitHub's own Pages build (`pages-build-deployment`) failed on `main` at `27fe278` because of it; CI itself stayed green because `npm ci` replaces the link. And checking a commit that tracks the link out over a real `node_modules` replaces the modules with a link to itself, a loop: at about 3:23 PM UTC (9:23 AM Central) on Tue, Nov 3, 2026, merging `main` into the trim's branch did exactly that to the main checkout, which broke every worktree's linked modules while two other builds were running, and `npm ci` rebuilt them. `main` now has a plain `node_modules` line in `.gitignore` and no tracked link (the trim's PR removed it). A revert of that merge or of the trim would put the link back, so a rollback is "revert the revert". Check any build that ran during an outage for failures the outage caused.
- **Every git command that writes a commit takes the owner's `-c user.name` and `-c user.email` pair**, not only `git commit`: merge, cherry-pick, revert and rebase too. The container's own git config names the session's tool, so a bare `git merge` records a tool's name and a no-reply address as author and committer. Every merge of `main` into a branch since then (`95ad25b`, `5eaf48f`, `ab0fbc3`, `5a3ae15`) carried the pair. That happened to the trim's merge of `main` (`9caac92`); the merge-safety review found it, and it was the one finding upheld, because a merge commit on a branch that merges with a merge commit stays in `main`'s history for good. The branch was rebuilt before the merge: reset to `2da1513`, the merge redone as the owner (`157ecd2`), and the repair cherry-picked on top (`190e118`), with an identical tree, then force-pushed with lease.
- **A live check compares the stylesheet and the switches chunk, never the main script's hash.** A Pages build gives the main script a different name from a local build's (checkpoint F, step 9 and the trim all showed it, and the live name even changed between two tries on the trim's check, from `index-e6206m2e.js` to `index-BL1DefRR.js`, as the Pages build landed). A loop that waits for the local main script's name never ends. Wait on the local stylesheet's name (`index-Dxhkeo-q.css` from pull request 122, `index-De3UpPLs.css` since checkpoint L) and on `features--b6t5tBm.js`, then read the rest. Checkpoint L's review found why the names differ: the Pages build sets the four `VITE_` values in `wrangler.toml`, and a local build with those four values set in its environment gives the Pages build's own files byte for byte. So the main script's live name can be predicted that way: checkpoint L's record named `index-BEO-j5HC.js` at 550,257 bytes for the Pages build, and the live site served exactly that on Tue, Nov 10, 2026.
- **A gate script runs the browser tests with `PW_CHROMIUM_PATH=/opt/pw-browsers/chromium`** (`PW_CHROMIUM_PATH=/opt/pw-browsers/chromium npm run test:a11y`). WS08 step 1's first gate script left it out, so the test runner looked for a browser that is not installed, and all 995 tests failed at launch in 8 minutes (10:09 PM to 10:17 PM UTC on Tuesday, November 3, 2026). The script was fixed and the run repeated. A browser run that fails everything within minutes is this, not a regression.
- **Check the date before a commit that touches the record.** The record's date line is the commit day in UTC, which a record test pins. A step built late in the evening can commit after midnight UTC (WS08 step 2's launch note says so). The lead reads `date -u` itself before committing and does not trust the builder's date.
