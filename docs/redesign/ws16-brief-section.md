## WS16 · Mail (the mail engine, lists and the LCA newsletter)
**Why:**
- Mail leaves the site through two calls to one service (Resend), with no unsubscribe, no record of a dead address and no list a person can leave. K, Tue, Nov 10, 2026: Amazon SES replaces Resend completely, with Resend as the fallback for event and account mail until SES has carried real mail cleanly for about 30 days (D31).
- K, Fri, Oct 23, 2026: "can i make a monthly newletter be hosted on the site for our leaders to collaborativly edit and it goes out automatically on the same date and time (unless edited) to a list of our members (email list given at first and then all new members get added with an opt-out feature)?" Part one sends it from today's Group email, written in today's text box with links pasted by hand (K, Tue, Nov 10, 2026: "much easier to use for now"); part two gives it its own page, built to K's picks (a person presses Send after a test and one confirm step, with "Send later" for a day and time), in the look the LCA president picks.
- Gmail and Yahoo ask senders of subscribed mail for one-click unsubscribe (RFC 8058) and every sender for SPF or DKIM and a spam rate under 0.3%; the FTC's CAN-SPAM guide asks commercial email to honor an opt-out within 10 business days, keep the opt-out working for 30 days after sending, and offer a choice to stop all where it offers a menu. K decided that no email carries a postal address (D41): the address duty applies to a message whose primary purpose is commercial, and an association's messages to its members are likely relationship messages, so the newsletter goes to current members and never sells membership to lapsed ones.
- Opt-outs kept in the site's own tables survive any change of service (D34), and a dead address that keeps being mailed hurts every email LCA sends. Amazon reviews a sending account at a 5% bounce rate or a 0.1% complaint rate.
- Group email has never been used on production (0 campaigns), so the engine can be put right before it carries real mail: today a cut run can send one message twice, and the batch sizes exceed the free plan's 50 outside calls an invocation.

**Canvas boards:** none for part one. The newsletter's design round (K, Tue, Nov 10, 2026: the page that hosts its writing and management, and how it looks when received) runs beside this plan, keeps to a simple first version for now, and feeds part two; K's picks are in, and the look of the page and of the email is the LCA president's pick among K's options.

**Data model**
```sql
-- 00xx_mail_lists.sql (0060 on the branch it lands on)
CREATE TABLE mail_lists (
  id TEXT PRIMARY KEY,                          -- 'lca-newsletter', 'lca-tournaments'; a club list's id is chosen in part two
  kind TEXT NOT NULL,                           -- 'newsletter' | 'tournaments' | 'club'
  name TEXT NOT NULL,                           -- what a person reads: 'LCA newsletter'
  main_mailer INTEGER NOT NULL DEFAULT 0,       -- 1 for LCA's main mailers, which a spam report made on other mail does not stop
  club_id TEXT REFERENCES clubs(id),            -- no cascade: a rebuild of clubs must never reach the choices on a club's list
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE TABLE mail_contacts (                     -- one row per address, a member's or not, so anyone can hold a choice
  id TEXT PRIMARY KEY,                          -- random, 32 hex characters; not a secret (a link's signature is)
  address TEXT NOT NULL,                        -- trimmed, lowercased
  optional_off_at TEXT,                         -- the person's own "Stop all optional email from LCA"
  complained_at TEXT,                           -- a spam report's mark: stops the lists that are not main mailers, by the setting
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE UNIQUE INDEX mail_contacts_address_unique ON mail_contacts (address);
CREATE TABLE mail_list_choices (
  contact_id TEXT NOT NULL REFERENCES mail_contacts(id) ON DELETE CASCADE,
  list_id TEXT NOT NULL REFERENCES mail_lists(id) ON DELETE CASCADE,
  choice TEXT NOT NULL,                         -- 'in' | 'out'
  source TEXT NOT NULL,                         -- 'link' | 'preferences' | 'complaint' | 'admin' | 'signup'
  updated_at TEXT NOT NULL DEFAULT (datetime('now')),
  PRIMARY KEY (contact_id, list_id)
);
CREATE INDEX mail_list_choices_list ON mail_list_choices (list_id, choice);
CREATE TABLE mail_do_not_send (                  -- dead addresses only: all mail to them stops
  address TEXT PRIMARY KEY,
  reason TEXT NOT NULL,                         -- 'bounce' | 'admin'
  detail TEXT,                                  -- the bounce's kind as Amazon names it, and nothing else of the notice
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
ALTER TABLE email_campaigns ADD COLUMN list_id TEXT;                          -- null for Group email's Specific people
ALTER TABLE email_campaigns ADD COLUMN skipped_count INTEGER NOT NULL DEFAULT 0;
ALTER TABLE email_campaign_recipients ADD COLUMN contact_id TEXT;
ALTER TABLE email_campaign_recipients ADD COLUMN sending_at TEXT;             -- written just before the send; never sent twice
INSERT OR IGNORE INTO mail_lists (id, kind, name, main_mailer) VALUES
  ('lca-newsletter', 'newsletter', 'LCA newsletter', 1),
  ('lca-tournaments', 'tournaments', 'LCA tournament email', 1);
-- no CHECK (the values live in domain/mail/lists.ts, held by a unit test); no table rebuilt;
-- the campaign tables' status CHECKs (0021, 0038) stay, so every state is written in their values
```

**Jobs & integrations**
- Amazon SES's v2 SendEmail over HTTPS, signed with AWS Signature Version 4 inside the Worker runtime (Web Crypto only, no package), through the configuration set `lca-mail` in `us-east-1` (assumed, Q48), with tags for the kind of mail and its list. Every email goes through `deliver()` in `functions/utils/mail/send.ts`, whose service is the server constant `MAIL_SENDER` (D31); the cutover is a pull request of its own after the switch-on, and waits for Workers Paid (settled by K, Q42); no message is sent by both services, and list mail goes only through Amazon SES (settled by K, Q41).
- Every answer maps onto the campaign sender's three kinds: sent; retry later only when Amazon's answer proves the message was refused for now (a throttle, a paused account, a key fault, a fault of the account's setup); never otherwise, an answer that may come after Amazon took the message included. A row is marked just before its send and never sent again; a list campaign is sent only by the list path, whatever `MAIL_LISTS_ON` says, and only by a deployment whose link key matches the one it was made with.
- Amazon SNS topic `lca-mail-events`, subscribed to `POST /api/mail/ses-events`, carrying the configuration set's bounces and complaints, with a delivery policy of about 50 minutes of tries. Amazon's account-level suppression list holds bounces only; SES's own email forwarding of reports is off.
- `workers/daily-emails` keeps its two crons and gains no phase (2.2): the five-minute sweep sends newsletter batches, and the daily run's reminders read one do-not-send query per phase, claim each row before its send and, under the engine's rules, run before the rating lookups. Batch sizes follow `WORKERS_PLAN`: on the free plan 10 a request, 20 a sweep run and 25 reminders a day, inside 50 outside calls and 50 queries an invocation; on Workers Paid 40 and 300 (D37).
- Secrets, never on the Preview environment: `SES_ACCESS_KEY_ID` and `SES_SECRET_ACCESS_KEY` (the Pages project's production environment and the worker), `MAIL_LINK_SECRET` (both; `MAIL_LINK_SECRET_PREVIOUS` only while a key is being changed) and `SES_SNS_TOPIC_ARN` (the Pages project). The key's policy allows `ses:SendEmail` on the sending identity and the one configuration set, from the sending addresses K decides from the address map (`noreply@louisianachess.org` alone until then).
- Resend stays the fallback for event and account mail until the clean period ends, then its code path, key and DNS records go (D31).

**Acceptance criteria**
1. Every email goes through one seam; with the switches off and `MAIL_SENDER` `'resend'` each request is byte for byte today's, and no file outside the transports names a mail service's address.
2. The SES sender signs inside the Worker runtime and passes AWS's published Signature Version 4 vectors; every answer maps to sent, retry later or never; an answer that may come after Amazon took the message is never tried again; a fault of the account's setup ends the run with the rows back.
3. No message is sent twice or by both services: one service a message, no fallback inside a send, a row marked sending never claimed again, and a list campaign sent only by the list path, whatever `MAIL_LISTS_ON` says.
4. The receiver acts only on a notification whose signature verifies under a certificate from SNS's host for our region, whose topic and account are ours and which is not more than three hours old; a second copy changes nothing; a not-spam report and Amazon's validation guess change nothing; it stores for a bounce only the address, its kind and the time, and for a spam report only the list's choice and the report's mark; a spam report never stops event or account mail, and never stops one of LCA's main mailers but the list it was pressed on.
5. No send path, the worker's included, reaches a mail service for an address on the do-not-send list or under a reserved top-level name, list mail never goes to the example domains, a loop reads its addresses in one query for each 90, and a gate that cannot be read lets event mail through and holds list mail back.
6. Choices are per list and keyed by address, so an address with no member account can hold one; an unsubscribe removes the person from that one list; event and account mail is never blocked by a choice.
7. A link is signed, cannot be guessed, never expires and needs no sign-in; the one-click POST works in multipart and urlencoded form with no cookie and no redirect, and a plain GET of the header's address leads to the page; opening a link or its page changes nothing; links and their pages keep working once a list email has gone, whatever the switches say.
8. Every optional email carries `List-Unsubscribe` (one HTTPS address) followed by `List-Unsubscribe-Post: List-Unsubscribe=One-Click`, the reason line, the unsubscribe and preferences links, and no postal address; event mail carries none of them.
9. The preferences page shows every list the person is on, on and off, saves and says so, and offers "Stop all optional email from LCA".
10. The newsletter goes to every address on an account with an active membership once and to no other address: families once; walk-in guests, reserved names and the example domains, the do-not-send list, people who turned it off and people who stopped all optional mail left out.
11. LCA admins with a second factor, the president and the media manager with a second factor may send; officers, plain members, club reps, an admin or media manager without a second factor and a former seat holder are refused; the media manager reaches only WS16's own endpoints, is refused every other part of Admin and keeps their own role's rights.
12. On the free plan's sizes no invocation, the daily run's included, exceeds 50 outside calls or 50 database queries, counted in a test; on Workers Paid's sizes a sweep run sends up to 300; Amazon SES sends only on Workers Paid.
13. Previews never send mail and never touch production; no test reaches an outside service.
14. With every switch off nothing a visitor or a member meets changes, and `test/a11y/baseline.json` is unchanged.
15. With `mailTools` on, the people who send see the addresses that no longer receive mail and the spam reports of the last 90 days (masked for the media manager), and only an LCA admin may clear an address, with an audit row holding the masked address.
16. After the clean period no code, binding, test catch point or living doc line of Resend remains, and the seam stays with its service a constant open to a second transport.
17. With `mailTools` on, Group email's member groups go out on the LCA tournament email list: each message carries its unsubscribe link and headers, honors that list's choices, a person's stop-all and the do-not-send list, never reaches a typed-in address, a hand-picked member or an account outside the list's audience (Q46), and a person who leaves it still gets the newsletter.
